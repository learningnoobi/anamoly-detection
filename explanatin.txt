# How 10 Flows Become 1 Prediction — The CLS Token Magic

This is what the CLS token does:
```
INPUT TO TRANSFORMER:
Position 0:  [CLS token]     (128 dims)
Position 1:  Flow 1          (128 dims)
Position 2:  Flow 2          (128 dims)
Position 3:  Flow 3          (128 dims)
Position 4:  Flow 4          (128 dims)
Position 5:  Flow 5          (128 dims)
Position 6:  Flow 6          (128 dims)
Position 7:  Flow 7          (128 dims)
Position 8:  Flow 8          (128 dims)
Position 9:  Flow 9          (128 dims)
Position 10: Flow 10         (128 dims)

Total: 11 positions

AFTER 3 TRANSFORMER LAYERS:
Position 0:  [CLS token']    (128 dims) ← this has "read" all 10 flows
Position 1:  Flow 1'         (128 dims) ← enriched by attention
Position 2:  Flow 2'         (128 dims)
...
Position 10: Flow 10'        (128 dims)

EXTRACT ONLY CLS:
h[:, 0] → (batch_size, 128)

CLASSIFICATION HEAD:
(batch_size, 128) → Linear(128→10) → (batch_size, 10)

RESULT:
One 10-element array per sequence
Each element = score for one attack class

## The Complete Learning Flow
```
INITIALIZATION (random weights):
input_proj.weight ~ N(0, 0.02)
cls_token ~ N(0, 0.02)
transformer layers ~ Xavier init
head.weight ~ N(0, 0.02)

EPOCH 1:
  ┌─ for each batch in train_loader:
  │    1. Forward pass
  │       bx → model → logits
  │       All 300k parameters used (no learning yet)
  │    
  │    2. Compute loss
  │       loss = CrossEntropyLoss(logits, true_labels)
  │    
  │    3. Backward pass
  │       loss.backward()
  │       → Computes gradient for ALL 300k parameters
  │       
  │       input_proj.weight.grad = ∂loss/∂input_proj.weight
  │       cls_token.grad = ∂loss/∂cls_token
  │       transformer_layer_1.attention.Q.weight.grad = ...
  │       head.weight.grad = ∂loss/∂head.weight
  │       (all 300k gradients computed via chain rule)
  │    
  │    4. Update weights
  │       optimizer.step()
  │       
  │       For each parameter:
  │         param = param - lr * adaptive_function(param.grad)
  │       
  │       ALL 300k parameters updated simultaneously
  │    
  │    5. Adjust learning rate
  │       scheduler.step()  (OneCycleLR gradually increases lr)
  └─ end batch loop

  Validate on val_loader (forward only, no updates)
  Save if best
  Check early stopping

EPOCH 2:
  Same process, but now:
  - Weights are slightly better than epoch 1
  - Learning rate is slightly higher (warmup phase)
  - Model should make better predictions → lower loss

...

EPOCH 100:
  - Weights have been updated 100 × num_batches times
  - Model should be well-trained (or early stopped)
